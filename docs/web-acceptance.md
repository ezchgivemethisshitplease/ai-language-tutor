# Local web acceptance, 2026-10-17

The browser host uses pinned official `@openai/codex@0.163.0` over stdio, independently of Desktop. Protocol/config contracts were checked against schemas generated by that binary and the official release sources. Online documentation can describe newer fields; this version does not have app-server `--ignore-user-config` or `readOnly.access`. The separate `CODEX_HOME`, disabled host tools/discovery and named restricted permissions profile are deliberate compatibility choices.

## Deterministic checks

The full local suite passes 188 Python tests, Ruff lint/format, mypy over 15 modules, compileall, three selfchecks and pip check. Added coverage consists of 20 bridge protocol tests, 15 controller/HTTP tests, eight launcher tests and three real process singleton tests. Node runs four activity transport scenarios and eight chat UI scenarios; all browser scripts parse. These use synthetic data and mocked model/protocol replies, not paid inference.

The bridge tests use real OS pipes to a controlled protocol fixture: interleaved response IDs, ordered events, callback-to-RPC calls, bounded frames/queues/timeouts, process death, approval rejection, unknown tool denial, environment isolation and credential redaction. Controller tests bind exact human messages to tasks registered earlier, keep LLM review provenance, reject invented audio/human signatures, preserve history in backups and cover failed disk writes, per-observation review identity, stale generations/turns, stream overflow and native CLI timeouts. Singleton tests run simultaneous real server processes and verify one learner host, URL reuse and stable lock identity.

## Actual local runtime and browser

`./start.sh --no-open --port 0` launched from outside the repository with an isolated learner directory. The page and token-protected health endpoint loaded and shutdown completed. No learner was initialized by launch/status alone. Local npm installation and exact CLI version checks passed; repeat setup reused the installed environment. The runtime remains inside the project and global host settings were unchanged.

A real isolated app-server initialized, returned unauthenticated account state and created a thread with the intended restricted profile. Native macOS sandbox probes read a harmless workspace marker, denied a harmless marker outside it, denied an in-workspace write and denied loopback network access that worked without the sandbox. These prove the tested macOS policy boundaries, not authenticated inference or a live Linux sandbox run.

The actual IAB opened the main web page and the official ChatGPT login page. The new isolated profile had no signed-in browser session; owner sign-in is required before the first model request. No tokens were read/copied from Desktop or the personal CLI, and no authenticated web-model result is claimed.

A separate synthetic IAB fixture exercised the real HTTP server/controller/frontend with a deterministic fake bridge: profile setup (15 minutes, Russian, work-email goal), first chat/task, server restart, conversation resume and the exact answer `Am  \n` including two spaces and a newline. Durable learner inspection found exactly one correct observation containing that exact string. The browser displayed the reply, history and saved plan without console errors. This is UI/persistence evidence, not a language-model teaching evaluation. Previous real card/quiz/reader browser checks remain documented in VALIDATION.md.
