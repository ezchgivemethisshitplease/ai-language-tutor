## Authenticated tool repair and teacher acceptance

The owner's first real chat exposed a missed integration failure: `gpt-6.1-sol` used the required `exec` wrapper to call `tools.tutor`, but the disabled code-mode host returned `code-mode host is disabled`. The mocked protocol suite and unauthenticated handshake could not detect model-required routing. The fix enables the bundled host at app-server startup and in thread start/resume configuration. It retains the restricted filesystem/network profile, declined approvals and existing general-tool disables. A full app-server restart is necessary; reloading only the page does not replace the old host provider. The sidecar lock created while reading the authored diagnostic bank is ignored without removing its stable inode.

An actual authenticated ephemeral model turn called the Python tutor callback and returned a random nonce supplied only by that callback. A separate real WebTutor fixture then replayed the two reported Russian requests against synthetic learner data. `status`, references, lesson start, item selection and registered diagnostic presentation all succeeded. After closing the controller/app-server and cold-resuming the same saved thread, the exact synthetic answer, including trailing spaces/newline, became one canonical observation; a second authored reading task was registered and presented. This used the project profile's official login without reading/copying credentials and did not modify the owner's learner or web-history bytes. The working server was restarted with the repair.

Real browser/authenticated-model interruption and prepared-activity combinations, broader teacher wording/humanize review and account/model variations remain separate checks. Subscription eligibility, rate limits and future model behavior remain service-controlled. The official app-server/dynamic-tool API is experimental and must be revalidated when updating the pinned version.

The web host now supports explicit local microphone dictation as described below; it does not score acoustics. Archive restore, emergency JSON recovery and real human progression attestation remain explicit owner CLI operations. No public deployment, multiuser support, offline Codex model, CEFR calibration or educational efficacy is claimed. The CLI/Claude workflow and earlier host-specific limitations remain documented separately.
